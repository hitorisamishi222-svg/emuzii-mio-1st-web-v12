# ガチャ受付スイッチの更新手順（スマホ用）

対象: PR #24 / release/v2-gacha-gate-connected
対象コード: [Code.gs](../Code.gs)
確認済み: 受付専用初期化・再実行・設定欠落・停止中の景品非取得・新規抽選拒否のローカルテスト5件合格。

## 1. 先に現行Apps Scriptのコードを照合する（必須）

今回共有された画面では、稼働中プロジェクトが「emuzii 翠央1周年 Web連携 v1.2」、Code.gs が「v1.9.1 LOGIN-ID」、さらに `GachaAdminV188.gs` など複数ファイルに分かれていることを確認した。

このプロジェクトへ、ブランチの Code.gs を全文貼り替える手順は使わない。既存機能を消したり、別ファイルと関数名が重複するおそれがある。先ほどの全文置換案内は撤回した。

安全な差分を作るため、現在のApps Scriptで次を確認する。

1. Code.gsを選び、上部の関数選択で `gachaAction_` を選択する。
2. 関数全体が読めるよう上部から末尾までスクリーンショットを送る。
3. 左側の `GachaAdminV188.gs` を開き、ファイルの内容もスクリーンショットで送る。

現行コードとの照合が済むまでは、関数の実行や既存ファイルの貼り替えをしない。画面上に既にある `setup()` も実行しない。ブランチの候補にある `setupGachaGate()` は、現行プロジェクトへまだ追加されていない。

## 2. 照合後に受付停止の修正版を反映する

現行コードに合わせて、既存の機能・補助ファイルを維持する最小差分を作ってから反映する。その後、受付スイッチ2項目が両方チェックなしになることを確認する。

参考として、ブランチの Code.gs は統合候補であり、現行プロジェクトへそのまま全置換するファイルではない。ローカルテスト5件は候補コードの確認で、実GASプロジェクトへの適合・稼働確認ではない。

## 3. 修正版を既存デプロイへ反映する

差分反映後に限り、「デプロイ」→「デプロイを管理」からVercelが接続中の既存ウェブアプリを編集し、新バージョンへ更新する。新規デプロイを作らず、既存 `/exec` URL とアクセス権を維持する。

## 4. 公開前の実環境確認

この操作だけではフロントエンドのPR #24は本番に反映されない。

実環境の接続確認では、停止中のガチャ一覧が空で、新しい抽選が拒否されることを確認する。ローカルテストは実際のApps Script稼働確認の代わりにはならない。
Vercelプレビューでは本番APIを遮断しているため、プレビューの503応答をGAS更新完了の証拠にはしない。

確認が済んだらPRのDraft解除とフロントエンドの公開作業に進む。運営の開始判断まで受付2項目は停止のまま。
