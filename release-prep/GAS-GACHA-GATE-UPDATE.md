# ガチャ受付スイッチの更新手順（スマホ用）

対象: PR #24 / release/v2-gacha-gate-connected
対象コード: [Code.gs](../Code.gs)
確認済み: 受付専用初期化・再実行・設定欠落・停止中の景品非取得・新規抽選拒否のローカルテスト5件合格。

## 1. 既存Apps Scriptのコードを差し替える

1. 現在のみおシステムで使っているApps Scriptを開く。スマホでは必要に応じてブラウザの「PC版サイト」を使う。
2. 現在のCode.gsを退避し、既存デプロイのバージョン番号を控える。
3. このブランチの [Code.gs](../Code.gs) を開き、Raw表示から全文をコピーする。
4. 既存プロジェクトの対応するCode.gsを置き換え、保存する。ほかのスクリプトファイルは変更しない。

SHEET_IDやBRIDGE_SECRET、Vercelの環境変数の変更は、この更新では不要。

## 2. 受付スイッチだけを設置する

1. Apps Script上部の実行関数で `setupGachaGate` を選んで実行する。
2. 管理スプレッドシートの `emuzii_管理画面` を開く。
3. 末尾付近のA列にある次の2項目のB列を、どちらもチェックなしにする。

| A列の項目 | B列の公開準備時の状態 |
| --- | --- |
| メンシプガチャ受付 | チェックなし（停止） |
| ラキフェス受付 | チェックなし（停止） |

4. `setupGachaGate` を再実行し、実行ログが `メンシプ=false, ラキフェス=false` であることを確認する。

`setupGachaGate` は管理画面の受付スイッチだけを設置する。既存スイッチのチェック状態は保持する。新設するスイッチは停止状態。
今回の更新では `setup()` の実行は不要。`setup()` は既存のガチャ回数計算式も書き直すため、受付スイッチの設置には使用しない。

## 3. 既存の稼働中デプロイを更新する

1. 「デプロイ」→「デプロイを管理」を開く。
2. 現在Vercelから接続している既存のウェブアプリを選び、編集（鉛筆）を押す。
3. バージョンで「新バージョン」を選び、説明に「ガチャ受付停止スイッチ」と入力してデプロイする。
4. 既存の /exec URL が維持されていることを確認する。実行ユーザー・アクセス権は既存設定を保持する。

参考: [Google公式・デプロイの作成と管理](https://developers.google.com/apps-script/concepts/deployments)

## 4. 公開前の実環境確認

この操作だけではフロントエンドのPR #24は本番に反映されない。

実環境の接続確認では、停止中のガチャ一覧が空で、新しい抽選が拒否されることを確認する。ローカルテストは実際のApps Script稼働確認の代わりにはならない。
Vercelプレビューでは本番APIを遮断しているため、プレビューの503応答をGAS更新完了の証拠にはしない。

確認が済んだらPRのDraft解除とフロントエンドの公開作業に進む。運営の開始判断まで受付2項目は停止のまま。
