# みおシステム v1.9.7 新端末の安全な本人確認・承認手順（開発用／未適用）

> **現状：本番GAS v12（v1.9.1）のまま。以下はv1.9.7と補助ファイルの修正・検証後に採用する案。今すぐ実参加者で試さない。**

## 基本原則
- 名前、8文字の旧ログインID、MIO-IDを知っているだけでは本人確認済みにしない。
- **既存端末の承認は保持**。管理者が対象のWeb登録IDを選ぶまで他の承認済み端末を失効させない。
- 自動補完・自動承認なし。運営が本人と既知の連絡経路で照合し、承認対象のWeb登録IDとMIO-IDを明示的に確認する。照合方法の証跡は番号・参照記録だけを管理用ログに記す。認証コードや個人情報本文を保存しない。
- 主キーはWeb-ID（特定ブラウザ）とMIO-ID（参加者本人）の組。**シートの行番号や名前だけで候補を選ばない**。
- 参加者原本・31日皆勤・ガチャ権利・当選履歴・FAには一切書き込まない。
- `emuzii_Web登録` の **実シート23行目は要確認のまま隔離**。本人確認なしの自動修復、他のIDへの統合、承認切替は禁止。

## 新しいブラウザ／端末の審査手順
1. **申請**：本人が公開サイトでColorSing名を登録すると、v1.9.7では既存名義との一致・短いログインIDの入力にかかわらず `承認待ち` となる。自動MIO-ID連携はしない。Vercelの `MIO_REGISTRATION_RELEASE` が停止中なら申請自体が503で止まる（GAS更新・検証後にのみ解除）。
2. **本人確認**：運営が過去から連絡を確認できる独立した経路で本人の端末切替意思を確認。新Web-IDの対象者と、保持したい既存MIO-ID（参加者台帳）を照合。名前一致は参考に留め、曖昧なら保留。
3. **候補の確認**：管理者が `emuzii_Web登録` でWeb-ID（A列）を特定。F=`承認待ち`、C=本人の登録名、B=tokenHashの存在、他の承認済みWeb-IDと照合。H/K/L/P/Tの不一致・異なるMIO-ID・却下済み／旧端末なら処理停止。**却下済み旧端末は新規承認せず、別途新ブラウザ登録を依頼**。
4. **運営が照合値を登録**：本人確認と参加者台帳への一意性照合を完了してから、対象Web-IDの **H=本人のMIO-ID、K=同じMIO-ID、L=`確認済み`** を設定する。Pは既存の計算式で得られる値を**上書きしない**。計算上のPがHと違う場合は処理停止。**F列はこの段階で変更しない**。誤ったH/K/Lの付与で他人のデータが見えるため、作業者とは別の確認を推奨。
5. **重複整理を更新**：`emuzii_重複整理` のN2で`更新`を選び、対象Web-ID(C列)・MIO-ID(B列)が合っているか再確認。候補が表示されないなら承認せず保留（管理画面の表示条件確認が必要）。
6. **明示的な操作**：本人確認済みの対象行だけ、I列=`確認済み`、続いてJ列=`このブラウザを追加`（旧端末を保持）または`この端末へ切替`（旧端末失効）。**後者は本人の切替同意を別途確認**。
7. **結果の確認**：K列の結果・L列の時刻、`emuzii_端末切替履歴` を確認。対象のF=`承認済み`・Q=`使用中`、H/K/P/L整合を確認。追加の場合は既存ブラウザがすべて維持、切替の場合は同一MIO-IDの旧承認Web-IDだけF=`却下`・Q=`旧端末`。他の参加者・皆勤・ガチャ・FAには変更がないことを確認する。
8. **エラー時**：処理を連続再実行しない。監査ログ・Web登録の対象行と旧端末行を照合し、差分が不整合なら公開停止のまま運営が判断する。

## v1.9.7 公開前に追加するプログラム安全ゲート
- `approveAdditionalBrowserV189Patch_`（現行追加承認）のWeb-ID一意確認後、対象F列が`承認待ち`であること、Q列が`旧端末`ではないこと、過去の端末切替で旧端末指定された記録に一致しないことを検査。既存承認済み端末の再承認・却下済み端末の復活を拒否。
- `switchApprovedWebRegistrationV189_` の切替対象も、F=`承認待ち`または`承認済み`以外とQ=`旧端末`を拒否し、切替実行前の本人照合を必須にする。
- **入力時のI=`確認済み`は手動の運営宣言**であり、本人証明そのものではない。監査ログの本人確認参照番号と操作権限を限定する。
- 古い`webRecoveryOnEdit_`を再生成する `setupV189Complete()`、`setupV187Complete()`、`setupWebRecoveryV189_()`を本番で実行しない。`setupBrowserAddV189Patch()`も再実行前にトリガー差分確認。
- 本番GASの公開中バージョン12には、この本人認証修正は**未適用**。新規ブラウザ登録はVercelのゲートを無効にするまで停止し続ける。

## 必須テスト（合成データで実施）
1. 承認済み旧ブラウザの通常利用に変化がない。
2. 新端末は同名・同旧ログインIDでも承認待ち、MIO-IDが自動的に付かない。
3. 本人確認と明示的なWeb-ID選択がない限り、追加／切替で権限を取得できない。
4. 旧端末・却下済み端末を`このブラウザを追加`で復活できない。
5. 追加で旧端末は維持され、切替で同じMIO-IDの対象端末だけ失効し、別MIO-IDは無変更。
6. H/K/P/L不一致、Web-ID重複、MIO-ID曖昧、本人確認未済ならfail-closed。
7. エラーや処理再試行時、半端な認証状態を残さない。
8. 実参加者データではガチャ抽選を試験目的で実行しない。

## 本番切替の順序
1. GASの本番プロジェクトを別途バックアップ。v1.9.7コードと端末管理補助の修正版を本番「編集状態」に反映（実データへのsetupやトリガー再作成なし）。
2. 承認済み既存端末の動作・端末追加と切替を別のテスト主体で検証し、現行ファイル間の重複する関数名やトリガーを確認。
3. **既存デプロイを更新**し、Vercel本番のGAS URLが同じデプロイIDを指すことを確認。新規デプロイURLへ勝手に置換しない。
4. Vercel候補の新規登録停止ゲートを解除する前に、運営による本人確認手順を確認。本人確認ができるまでゲートを解除しない。
5. 本番サイトのメンテナンス解除は別途承認。公開後のエラー監視と切戻し経路を確保。
