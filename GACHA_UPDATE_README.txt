v1.9.2 ガチャ設定・本番反映メモ

【ガチャ権利】
・1ヶ月メンシプ = 1回
・3ヶ月メンシプ = 2回
・6ヶ月メンシプ = 3回
・運営の特別付与は emuzii_ガチャ「特別付与」で加算

【ラキフェス】
・総ガチャ権利5回以上が対象
・手動消費では解放しない
・Webで実際に4回の抽選を完了した後、5回目の抽選からラキフェスを選択可能
・画面ボタン、Vercel API、Google Sheets管理表示の3段階で制御

【Web参加者MIO-ID統合】
・予想フォーム未回答でもWeb登録から参加者マスターへ追加し、MIO-IDを発行できる
・ColorSing名が一意に一致する場合のみWeb登録H/K列へMIO-IDを自動接続する
・同名が複数ある場合は自動確定せず「重複要確認」とする
・登録承認、メンシプ確認は自動化せず運営確認を維持する
・登録直後の数式反映が遅れた場合は status / catalog / history / draw / checkin 時に再照合して自己修復する

【景品設定】
・正本は Google Sheets「emuzii_景品設定」
・通常ガチャ／ラキフェスは、みおが後から管理シートで景品と確率を設定できる
・各種類ごとに有効景品の確率合計が100％になった時だけ抽選可能
・景品設定が未完了、確率合計が100％以外、景品ID重複、数量上限到達がある場合は抽選停止
・有効な景品は画像URLを必須運用
・景品名、レア度、確率、有効/無効、数量上限、画像URL、運営メモ、被り判定キーを管理可能
・当選済み景品は被り判定キー（空欄時は景品名）で除外し、同じ参加者に同一景品が出ない

【受付スイッチ】
・管理画面側のスイッチで、メンシプガチャ／ラキフェスを個別に停止できる
・停止中はWeb画面のボタン名が「停止中」になり、押せない
・Web画面は30秒ごと、フォーカス復帰時、表示復帰時に設定を再取得する

【皆勤賞】
・確認文字は各日2回まで
・2回不正解後はロック
・正解済み日は再入力不可

【端末変更・復旧】
・新端末では以前と同じColorSing名で再登録する
・同名が一意なら既存MIO-IDを復旧先候補として自動照合する
・運営が新端末のWeb登録を承認し、動作確認後に旧端末の登録承認を「却下」へ変更する
・MIO-ID、皆勤、FA、ガチャ権利、当選履歴は維持し、Web端末登録だけを切り替える
・同名の別人が存在する場合は自動確定せず、運営が参加者IDを確認する
・同一名で複数のWeb登録が同時に承認済みの場合は管理画面で警告する

【安全仕様】
・抽選IDで同じ抽選の二重確定を防止
・結果はサーバーで先に確定保存し、その後に演出表示
・当選履歴の「確定」だけを本番集計に使用
・テスト無効の履歴は本番回数に含めない

【更新ルール】
・既存GitHubリポジトリ hitorisamishi222-svg/emuzii-mio-1st-web-v12 を維持
・既存Vercelプロジェクト emuzii-mio-1st-web-v12 を維持
・新しいリポジトリ／Vercelプロジェクトを作らない
・固定URL https://emuzii-mio-1st-web-v12.vercel.app/ を維持
・公開中データを消さない、古い版で上書きしない
・mio-awakening.mp3 と mio-blue-bg.png は維持

【注意】
・GitHubの古い Code.gs は過去版が残っているため、Apps Scriptを更新する場合は APPS_SCRIPT_Code_v1.8.6.gs を基準にし、現行のVercel API側ラキフェス制御を維持すること。
・GitHub上のApps Script参照ファイルを更新しても、公開中のGoogle Apps Script Webアプリは自動更新されない。ライブGAS側へコード反映・再デプロイ後に本番反映となる。
