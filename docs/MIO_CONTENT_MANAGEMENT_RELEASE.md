# みおシステム vNext — お知らせ・音楽・動画管理の公開前確認

更新日: 2026-10-28
対象: ドラフト PR #43 の開発ブランチ。稼働中の本番環境は変更しない。

## お知らせ管理の現状
- 既存 `announcements-manage.html` → `/api/gallery/announcements` で新規作成・編集・公開・非公開・削除が実装されている。重複する管理ツールは作らない。
- 今回 `api-announcements.js` のリクエストごとの `CREATE TABLE` を廃止。既存の専用ギャラリーDBに必要なスキーマは `db/announcements.sql` として独立させた。テーブルがなければサービスはエラー表示し、ユーザー操作のついでに作成しない。
- `announcements-manage.html` の操作後に編集ボタンが戻らない問題を修正。保存に失敗した際、下書き中の入力値を保持する。
- 公開ページ `announcements.html` は既存の発表を保持し、管理者が公開したお知らせを追加表示する。

## 音楽・動画管理の現状
- 既存 `music-gallery.html` はギャラリーへの案内で、音楽・動画の独立した管理画面はなかった。
- `media-manage.html` を管理者メニューから開く。既存 `/api/gallery/moderate` の権限チェックで管理者・承認端末だけに編集フォームを表示する。
- 音楽・動画の新規登録・既存応募編集: タイトル、掲載名、作品説明、HTTPS作品URL、サムネイルURL、カテゴリ、権利確認の同意。新規・更新後は必ず `pending` となる。
- 新規作品の審査は既存の vNext `gallery-submissions-admin.html` を使う。新しいDBを別に作らず、`gallery_submissions` に統合。
- サムネイルは `/assets/...` または認可された Vercel Blob 配信URLのみ受け付ける。危険なスキームや任意の画像ホストは拒否。
- 管理者の編集もトランザクションで監査履歴を記録し、改訂番号が一致しない場合は失敗させる。
- 公開ページ `/api/gallery/items` は `status='approved'` の新規作品だけを別の明示的公開フラグがある場合に追加。既存固定作品の表示を優先し、任意の新規テーブルの障害で既存作品の表示を停止しない。

- [ ] `db/announcements.sql` と `db/gallery-submissions.sql` の既存スキーマを照合。まだ勝手に適用しない。
- [ ] `MIO_GALLERY_SUBMISSIONS_ENABLED` は受付停止を既定として維持。受付開始時のみ `true` を設定。
- [ ] `MIO_GALLERY_SUBMISSIONS_PUBLISH_ENABLED` は新規作品の掲載停止を既定として維持。承認済みのみ公開されることを確認後に `true` 設定。
- [ ] 管理者セッション・承認端末から、新規登録→審査待ち→承認→掲載→非公開→復元の実DB動作を検証。
