# 既存GAS稼働ソースの非公開バックアップ照合（2026-11-02）

**目的：** 翠央1周年の既存 Apps Script を壊さず、Web管理19関数と`doPost`の現物を判定する。**本番GASへ書き込むツールではない。** GitHubの`main`や保存された`.gs`ファイルと、現在のApps Scriptエディタにあるコードが同一とは限らない。

## 手順（運営の許可・実際の管理画面から取得する場合のみ）

1. 既存管理シートから「拡張機能 → Apps Script」を開き、**既存プロジェクト名・デプロイID・現行デプロイ版**を管理者が確認。秘密鍵・スクリプトプロパティ・参加者データは第三者へ送らない。
2. 稼働スクリプトの**すべての `.gs` ファイル**を、手元の非公開フォルダへそれぞれ保存する。アプリのデプロイを変更・追加しない。バックアップ原本には編集をしない。対象ファイルが不明・取得できない場合はここでSTOP。
3. Node.jsの使えるPC上で、このリポジトリの開発ブランチを用意し、読み取り専用CLIを実行する。ファイル名は例。**実行時の引数には本当に保存した全`.gs`ファイルを渡す**。

```bash
node scripts/mio-gas-source-preflight.mjs "/private/backup/Code.gs" "/private/backup/Other.gs"
```

このスクリプトは、ソースを解析して**関数数・重複数・`doPost`数・BRIDGE_SECRET確認が管理ルートより前か・ScriptLockの取得と失敗時returnが管理処理より前か**を表示する。秘密鍵・コード全文・参加者情報の値はログに出さない。読み取り以外のファイル操作、Spreadsheet/GAS/DBへの接続はしない。CLIは安全が確定しない限り**終了コード0を返さない**。

| 判定 | 意味 | 次の対応 |
|---|---|---|
| `NO_OPS_CANDIDATE_ONLY` | 管理19関数なし・`doPost`が1つ。保存済み旧版に相当する構造 | 既存バックアップと現行デプロイ版を照合。認証・ロック内でのルート差分を設計。**自動追加禁止** |
| `ALL_OPS_IN_SOURCE_UNVERIFIED_DEPLOYMENT` | 管理19関数が1回ずつあり、管理ルート順序の静的条件を満たす | **すでに管理処理がある可能性**。追加ファイル不要か確認。現行デプロイと一致するか別途実機確認 |
| `BLOCKED_REVIEW` | 関数の重複、部分追加、`doPost`重複、認証順序/ロック異常など | **変更・デプロイ停止**。現物コードを非公開で修正レビューしてから再判定 |

**重要：** この検査はソース文字列の保守的な静的確認で、認証やロックの実行経路を保証するものではない。危険な順序・失敗時return欠落は停止判定にするが、判定が良好でも管理者によるコードレビュー、現行デプロイ照合、バックアップ、読み取り専用の実機確認が別途必要。

## 既存管理シートで確認済みの安全停止条件

- `emuzii_Web登録`のログインIDは**21列目**、`emuzii_ガチャ`は**17列**の想定と一致。
- **`emuzii_ガチャ付与履歴`のJ列には`Web操作ID`見出しがない。**
- **`emuzii_Web管理操作履歴`のタブが現行のシート一覧にはない。**
- これらのタブ/列を作成する動作は**データのスキーマ変更**なので、必要性とバックアップ、付与/景品/当選履歴の整合、運営の明示承認が揃うまで一切行わない。
- `MIO_GACHA_ADMIN_OPS_RELEASE`はOFF。書き込み操作・管理承認・回数付与を実施しない。
- 結果が`ALL_OPS_IN_SOURCE_UNVERIFIED_DEPLOYMENT`でも、それだけで本番のGAS実コード・デプロイ版の一致は確認できない。
- `mioAdminOpsRead_`の候補コードにSheet書き込みがないことは静的確認済みだが、実稼働版の確認は未実施。**接続確認は段階的・読み取り専用が先。**

## 2026-11-02 16:45以降：確定済みの監査だけを信用しない再送検証

**今回の問題**：保存済みGAS候補は、操作IDに対する監査履歴が `確定` の場合、下流の実データ（付与履歴、承認済み登録、参加者ID）を再確認せずに「再送成功」を返していた。監査と実データが欠損・改変した場合、操作IDの再送が誤った「正常」を返すリスクがある。

**開発版で追加した保護（稼働GASには未反映）**
- ガチャ券の付与：`mioAdminOpsGrant_` は確定済み操作の再送でも、同じ操作IDに対応する `emuzii_ガチャ付与履歴` の記録が **1件だけ存在し、MIO-ID、対象名、付与回数、理由、前後残数が一致**するか `verifyOnly` で読み取り照合。欠損・改変・重複があれば例外にして、履歴の追記や残数付与を自動で行わない。正常な再送では書き込みゼロ。
- 承認：確定済みの再送でも、実際のWeb登録の承認状態、紐付けMIO-ID、本人確認、メンシプ照合、旧端末の否定、同一IDの他端末承認なし、既存参加者名とWeb登録名/監査名の一致を読取確認。不一致なら停止。確定済み監査行は再書込みしない。
- 新規MIO-ID：確定済みの再送でも、監査に記録されたMIO-IDの形式、元のWeb登録名、既存参加者テーブルにある **同ID・同名の行が1件だけ存在**することを読取照合。変更・欠損時は停止。既存IDを新たに発行せず、監査を改変しない。
- 単独GAS候補、全統合GAS候補、非公開コピー用HTMLを同じ内容に同期した。モックの参加者ID列は実Sheetの式で表示される値を一括読取でも再現するよう修正した（本番Sheetの数式には触れていない）。
- 専用テストには、確定付与履歴の欠損/改変/二重記録、確定承認の取消・本人確認不一致・旧端末・参加者名改変、確定新規IDの参加者削除/名前変更を追加。異常系では **副作用ゼロ**を検査。
