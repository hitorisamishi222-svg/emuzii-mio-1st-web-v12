# MIO大型アップデート：みお発行ID・1人1端末・3階層ミュージアム

状態：**隔離設計／コード・画面試作**。本番のID発行・ログイン・部屋開放は未実装・未公開。

## 2026-11-23 確定指示

1. みおが管理画面から発行者（現在みお）と発行対象者を登録し、利用者へ発行IDを渡す。
2. 利用者は「発行者確認→ID入力」画面から初回登録。ランク別に自動ログイン・入室（一般公開・登録歌推し・メンシプ）。
3. 1人1端末。機種変更・キャッシュクリア等で認証を失った場合はみおが新しいIDを発行し、旧ID/旧端末のログイン権限を即時失効。
4. 現在複数端末の利用者も移行後は1台に統一。既存 MIO-ID・皆勤・ガチャ当選結果・残回数・履歴は保護。
5. 全利用者向け承認操作を繰り返さず、みおがID発行・ランク変更・再発行・停止を1画面から操作できるようにする。

## 実装の境界

- 公開MIO-IDは識別子であり、単独では秘密の部屋にログインさせない。みおが渡す高エントロピーの **使い切り発行ID** が初回認証情報。
- 初回登録後は使い切りIDを破棄し、HttpOnlyセッショントークンとブラウザの非抽出可能な端末鍵で認証。端末鍵のECDSA-P256署名検証器は**隔離試作済み**。ただしDBでチャレンジを使い切り消費し、招待ID請求と同一トランザクションで処理する内部関数は**隔離実装済み**。HTTP API接続・実DB検証・iPhone実機確認は**未実装**。試作Coreは検証済みproofのみを受け付け、公開APIを接続していない。
- 端末変更再発行は既存master_idを引き継ぎ、世代番号更新とDBセッション/端末鍵の失効を同一トランザクションで行う。**古いCookieは新しいIDに移行した瞬間から無効**。
- 登録済み複数端末の排除は、GAS/旧 `/api/status` `/api/checkin` `/api/gacha` `/api/enroll-lite` の**全認証経路**が新しい単一端末セッション照会を実装してから有効化する。新方式だけONにしても旧端末経路が生きるので「1人1台」を保証できない。
- ネット回線/IPの変更はそれだけでは認証無効にしない。キャッシュ消失や端末鍵喪失時に再発行で復旧。盗難時の管理者即時停止が必要。
- メンシプは有効期限つき。期限切れ時は自動で「登録歌推し」に戻し、既存の皆勤・ガチャ付与には触れない。権利付与は管理者の資格確認が必要。
- 画像/動画の限定配信はサーバー認証付きAPI経由（公開静的ファイルURLから直接取れない保管形式）に変える。今の公開 `/gallery.html` 資産のアクセス権は変更しない。
- SEO用の公開館は引き続き無ログイン。一般歌推し・メンシプはアクセス拒否がサーバー側で働くこと。

## この隔離試作で実装した機構

- ランクと3部屋の権限判定。
- 発行IDは暗号学的乱数128bit、HMACハッシュのみDB保存。
- 発行・再発行で旧セッションと未使用旧IDを失効。コード使用は単回のみ。
- 本人の非抽出可能な端末鍵の署名検証器とproofガード（ワンタイムチャレンジを原子的に消費するバックエンド接続は別工程）。
- ID/メンシプランク・期限確認を毎回DBで判定し、旧Cookieを拒否する形。
- 本番テーブルとは独立した試作用SQLマイグレーション。

## 第112巡｜データ保護・ロールバック検証（隔離）

- 2026-11-24 現在、PR #94は未統合、PR #96はDraft。本番の登録・ガチャ・皆勤は変更しない。
- 既存MIO-IDと「発行ID」を別物として扱う。再発行で無効にするのはその人の発行ID・旧認証セッションであり、MIO-ID、皆勤・ガチャ履歴、残回数、確定当選は削除しない。
- 既存の複数端末登録会員を一括失効させない。1人ずつ本人確認、新端末の署名確認、資格照合の後に移行し、完了前は現行認証を維持。
- 「1人1台」には旧登録・皆勤・ガチャ・復旧の全認証経路で同一の端末世代・鍵検証が必須。いずれか未実装なら本番移行は不合格。
- mio-issued-cutover-guard.mjs は書込みのない単一会員の事前判定器。オーナー認証、GAS正本ID唯一性、3種類のデータスナップショット、端末署名、旧API遮断、PR #94互換、並列テスト、ロールバック試験などが全て合格でも READY_FOR_MANUAL_RELEASE_REVIEW のみ返し、公開や権利変更はしない。
- simulateMioTransfer は旧端末2台から新端末1台への切替をメモリ上だけで検証する。旧会員データは変更しない。
- 隔離スキーマのチャレンジ表にあった二重定義と途中欠落を修正し、静的検証を追加。実PostgreSQL構文実行を伴っていないため、本物のDBでの合格ではない。

### 非破壊的なロールバック方針

1. 将来問題が出た場合、新規発行と新規移行のみ停止し、公開URLを維持。
2. 影響対象のMIO-ID、操作ID、端末世代、資格、皆勤とガチャの読み取りスナップショットを照合。認証秘密やCookieは記録しない。
3. 失効済み旧IDや旧Cookieは自動再有効化せず、みおの本人確認で安全に再発行する。
4. 既存GAS台帳や確定履歴への自動逆書込み・削除・一括更新は禁止。既存会員の移行を一人ずつ保留できる。
5. 公開・マージ・フラグ変更・本番データ移行は第112巡で行わない。
