## 運用ルール
- 一般の来館者: 登録なしで公開展示だけ閲覧。表示件数0のとき、架空のアイコンやイベント名を作らず「展示準備中」と案内。
- 管理者: `gallery_admin_users.role='owner'` ＋既存の認証済みセッション＆承認済み端末に限定。他の管理者・一般参加者は編集不可。
- 新規登録は `draft`、編集した公開済み作品も `draft` に戻る。下書きから公開する際には、作品の権利とスクショの個人情報を再確認する。
- 管理者の操作は楽観ロック（revision）で競合を検出し、監査ログと同一DBトランザクションに保存する。
- 公開停止は `hidden` に変更するだけで実ファイル削除ではない。投稿権利やプライバシーを理由とする撤回は、画像保存先の削除・失効も別途対応。
- `MIO_MUSEUM_ARCHIVE_EDIT_ENABLED` と `MIO_MUSEUM_ARCHIVE_PUBLISH_ENABLED` はどちらも初期OFF。権限・DB・公開範囲を確認したうえで**別々に**ONへ切替。
- 画像の直接アップロードは未対応。既存サイト内 `/assets/` またはVercel Blobの公開URLを使う。連絡先、端末ID、MIO-ID、個別チャット画面のスクショは許可・必要なぼかしなしに掲載しない。
- **翠央専用の宝箱は今回のテーブルに保存しない。** 第3段階でオーナー専用の非公開ストレージ、サーバー側アクセス制御・ファイル提供経路を個別設計する。

## スマホ画像登録機能（2026-10-28 追記）
- `museum-curate.html` にスマホ画像選択、プレビュー、取消し、本人の権利/個人情報確認を追加。
- `museum-image-client.js` で **端末内で最大1600px程度に縮小、WebP/JPEGへ再エンコード**。EXIFなど元ファイルのメタデータをそのまま転送せず、サーバー送信は縮小画像と作品の公開用メタデータのみ。最大12MBの入力を選べるが、圧縮後の画像は700KB以下である必要がある。対応できないHEIC等はエラー表示して中止。
- `api-museum-image.js` は **画像と展示説明を同一操作で下書きとして保存**する。既存の管理者認証・承認端末・ownerロールを確認し、連続する編集の版数を照合。新規画像Blob保存後にDB更新と監査ログを1トランザクションで確定し、保存処理がDBのCOMMITに到達する前に失敗した場合は新規Blobを削除する。**COMMIT結果が通信障害で不明な場合は、DBから画像だけが消える事故を防ぐため画像を残し、後日の整合確認対象とする。**
- 上書き更新では既存の展示を必ず `draft` に戻す。画像の再アップロードが完了しただけでは展示を公開しない。公開操作時に権利確認とスクショの個人情報確認が再度必要。
- Vercel Blobは既存ギャラリーと同じライブラリを利用。**公開Blobに保存するため、下書き画像であってもURLが分かれば閲覧できる。** 非公開スクショ、個人情報入り画像、宝箱用画像は絶対に扱わない。公開保存先が安全に準備できるまでは機能を停止する。
- 画像登録フラグ `MIO_MUSEUM_IMAGE_UPLOAD_ENABLED` は初期値OFF。編集フラグ `MIO_MUSEUM_ARCHIVE_EDIT_ENABLED` もONにならない限り画像登録は使用不可。既存 `BLOB_READ_WRITE_TOKEN` と専用DBの用意・管理者端末の実機検証が前提。
- `api-museum-exhibits.js` のオーナー向けGETのみ、画像登録の可否（秘密値そのものではない）を返す。一般来館者のGETは画像登録情報を受け取らない。
- 保存に成功した場合でも旧Blobは自動削除しない（同じ画像URLの別の利用者や履歴を壊さないため）。将来の管理画面から削除申請・参照確認・安全な清掃を別機能として検討する。
- `tests/mio-museum-image.test.mjs` は機能停止、誤Origin、画像形式、未認証/非オーナー拒否、下書き保存、競合、監査失敗時のBlob削除、成功時の旧Blob保護を重点検査。画像圧縮の実機性能とSafari/AndroidのHEIC表示、実DB＋実Blob動作は未検証。
- 受付用の外部サービス、追加のGitHubリポジトリ、GAS、参加者データ、皆勤、ガチャ、本番 main は変更しない。
