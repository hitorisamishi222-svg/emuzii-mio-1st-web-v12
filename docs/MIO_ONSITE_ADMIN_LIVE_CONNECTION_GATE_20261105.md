## 現場向け追加保護（2026-11-05 最終候補）

- **簡易受付の行番号だけでは確認操作できない**。管理APIは初回に読み取った受付日時（A列）・ColorSing名（B列）・簡易登録ブラウザID（C列）を必須にし、GASも台帳原本と照合。不一致なら監査記録を書かず停止。A列の日時書式が旧型のUTC文字列でも、読み取り時の原文をそのまま照合する。

## 2026-11-06 実装準備：承認済みメンシプ確認を独立ボタン化

管理Webの既存画面とAPIに、次の**個別確認操作**を準備した。新規登録・本人照合と承認・ガチャ回数付与に加え、**既に承認済みの参加者のメンシプ購入確認だけ**を行える。画面では対象参加者を検索・選択し、その人の**本人確認済みの既存ブラウザ1件**を選択して、購入確認チェックと最終ボタンを押す。IDの再登録やコード貼り付けは不要。

- GAS候補アクション `webAdminOpsMember` は、既存の `BRIDGE_SECRET` 照合後、同じ `ScriptLock` 内の管理分岐で処理。対象Web登録ID、MIO-ID、元登録名、H/K/L/P列の整合、承認済み状態、旧端末除外をすべて検証する。

- 操作はUUIDベースの既存管理操作IDで監査シートに記録する。通信切断で結果不明の場合、**同じID**で再照合し、再度の書き込みをしない。監査記録が壊れている場合は停止。確定済みのメンシプをもう一度「確定」し直さない。
- 管理UIには承認済みブラウザと状態を読み取り専用で表示する。旧端末やWeb本人確認・統合IDの不整合がある端末には操作ボタンを出さない。取得に失敗したときは以前のボタンを消して、書き込み不可に戻す。
- 管理API は `member` を `webAdminOpsMember` にのみ割り当て、現場の個別確認フラグと管理者認証の双方がなければGASに到達しない。独立したガチャ権利付与ではない。
