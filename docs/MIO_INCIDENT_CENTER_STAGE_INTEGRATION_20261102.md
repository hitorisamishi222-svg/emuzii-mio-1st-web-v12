## 追補：監査再送と障害一覧の不完全応答を拒否（開発ブランチのみ）

- `mio-incident-core.js` の `transitionIncident` で、同じ操作IDの再送時に監査行の `after_state` も照合する。監査の操作名/事前状態/操作対象/ペイロードだけが一致していても、**記録済みの事後状態が不正・欠落していれば成功とはしない**。トランザクションはロールバックし、障害状態を追加更新しない。
- `listIncidents` では、DB応答が欠落・行数不一致・不正な行を含む場合、**「未対応0件」として返さずエラーにする**。真正に `rowCount:0,rows:[]` が返った場合のみ空一覧と区別する。Web管理センターに本番APIを接続したものではない。
- `tests/mio-staged-incident-core.test.mjs` に監査事後状態の改変/欠落、障害一覧の部分応答/行数不一致/異常状態、個人情報の余剰フィールドを応答へ転記しないことを検査する3テストを追加。
- 対象は既存大型更新の **Draft PR #76 の未配備コードと模擬DBのみ**。障害管理APIは未公開、SQLは未適用、実稼働GAS・Neon・管理シート・MIO-ID・ガチャ回数・皆勤・当選履歴・既存公開URLには変更しない。
- **残る停止条件：** 稼働GASの全ソースとデプロイ版/復元バックアップ、既存操作監査スキーマの承認、DB正本と実管理者権限、旧抽選履歴との突合、実機テストおよび全回帰CI。上記が揃わなければ公開せずDraftを維持。

## 2026-11-02：監査欠損・通信断で誤復旧しない再送保護（Draft限定）

- `mio-incident-core.js` の処理済み **START** を遅れて再送した場合、現在の障害状態が `resolved` であっても、同じ障害に対する **resolve監査が正確に1件存在し、ペイロードハッシュが一致する**ことを読み取り確認する。不在・改変・重複なら誤った成功を返さずロールバックする。解決状態へ直接書き換えただけでは成功扱いにならない。
- `transitionIncident` の操作ID監査読取について、DB応答の `rowCount` 欠落、行数矛盾、行配列欠損、不正型を**「監査なし／新規操作可能」と誤判定しない**よう停止する。再送で余分な状態更新を行わない。
- `recordIncident` のINSERT応答が0行・1行いずれの場合も、実際に受け取った行配列の長さと `rowCount` が一致することを要求。通信異常を「登録済み」や「レート制限で未記録」と取り違えない。
- 追加の模擬DB回帰は `tests/mio-staged-incident-core.test.mjs` に保存。**実Neonにマイグレーション・SQL実行を行っていない**。現行本番の障害APIは未作成、現行VercelやGASの認証・抽選・回数・皆勤・当選履歴には変更なし。
- この検証で証明できるのはモックとコード経路のみ。**通信断によるDBのCOMMIT結果不明、真の同時リクエスト競合、実接続でのロックと監査整合性は未確認**。稼働GASの全ソース/デプロイID・復元バックアップ、正本DBの確認、管理者権限、実機検査、正式な公開承認が揃うまでPR #76はDraft、各リリースフラグOFFを維持する。
