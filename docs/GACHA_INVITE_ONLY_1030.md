# 10/30 招待ガチャ（会員登録を求めない・一時利用）

## 意図
特設サイトに興味がない人もガチャだけ参加できる。これはログイン障害の救済ではなく、
別の参加導線。本人は `gacha-invite.html` の招待コード1つだけ入力し、会員登録・皆勤・FAは不要。
ただし管理側では、抽選不正と二重消費を防ぐため専用Web参加IDを**内部的に**発行する。

## 既存システムとの共通点
- `emuzii_参加者` / `emuzii_ガチャ` の**正規MIO-ID**に結びつけ、残回数は共有。
- 既存 `gachaAction_` を呼ぶ。景品、確定当選履歴、通常/ラキフェスを横断した被りなし条件は共通。
- `api-gacha-invite.js` の専用cookieは Path=/api/gacha-invite に限定。通常サイトの `mio_session` を発行せず、皆勤などのAPIには使えない。
- 通常ガチャとラキフェスは現在どちらも公開OFF。**この入口では自動でONにしない**。抽選できる時刻は管理者の既存スイッチに依存する。

## 参加者の流れ
1. 管理者が本人とメンシプ購入口数を確認する。初来訪者は管理側だけで正本にMIO-IDを用意・既存ガチャ回数を付与（本人にフォーム入力を求めない）。
2. 管理者が既存GAS内で `gachaInviteIssue('MIO-xxxx',48)` を実行。発行時にだけコードが表示される（台帳にコード平文を記録しない）。現在は管理者向け1クリック発行UI未実装。
3. コードと専用URLだけを本人に渡す。本人はコード1回入力。同じ端末なら7日間Cookieで継続。
4. 利用可能回数、通常/ラキフェスの受付状態を確認して抽選。すべて同じMIO-IDの既存確定履歴に記録。
5. 入力コードは**使用済み**となり、別端末には流用不可。紛失・端末変更は管理者が確認して再発行。

## 安全設計
- 16桁16進数（約64ビット）のランダム・一度だけ使えるコード、標準48時間、設定可能1～72時間。
- 台帳保存はSHA-256のみ、コードは発行時1回表示。管理者2名のGoogle本人照合が必要。
- GAS `doPost` の既存ScriptLock内で使用済み処理。二つの端末による同時使用を拒否。
- 通信結果不明時には短命の署名Cookieで同一IDのみ再送可。別端末で再使用不可。
- 抽選直前に管理台帳で残数・当選履歴・メンシプ承認・公開スイッチをサーバー再検証。
- ユーザー端末の前回抽選IDを保存。結果が不明な場合に新しい抽選を要求せず、元履歴を照合。
- Vercelの `MIO_GACHA_INVITE_RELEASE=verified-gas-invite-20261030` がない限り専用APIは503（準備中）。Previewでは `prepare()` もブロック。
- 招待画面には元サイトの登録欄、パスワード、皆勤項目は表示しない。
