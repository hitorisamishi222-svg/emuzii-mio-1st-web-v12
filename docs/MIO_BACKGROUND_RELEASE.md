# vNext 姫／魔王 背景切替 — 公開前チェック

更新日: 2026-10-28
対象: ドラフト PR #43 の開発ブランチ。正本 main・本番URL・稼働GASは未変更。

## 確定仕様
- サイトのトップ `index.html` と翠央っ子ギャラリー `gallery.html` のみ、管理者が選んだ姫・魔王背景を反映する。
- 既存素材 `/assets/mio-bg-princess.jpg`, `/assets/mio-bg-devil.jpg` をそのまま使う。新規素材の生成や画像の削除はしない。
- トップの `<picture>` 内 `source.srcset` と `img.src` を同じ画像へ切り替え、空白化を避ける。ギャラリーの `role=img` ラベルも切り替える。
- ガチャページは `data-mio-background` の対象外。既存の姫・魔王ガチャ演出に変更を与えない。
- データベースからの読み込みが失敗した場合、標準の姫背景のまま。保存はしない。
- 既存の `api-gallery-moderate.js` と同じセッションCookie＋承認済み端末Cookieを照合。管理者以外の書き込み不可。
- `POST /api/background` は同一オリジン、JSON、theme=princess/devil、revision一致、監査ログ記録を要件とする。
- 設定変更と監査ログは同一DBトランザクション。競合・エラーならROLLBACKし、操作を成功扱いにしない。
- 管理画面は `configured:false`（未移行DB）時に保存ボタンを無効化する。競合・不明な保存失敗時は設定を読み直すまで再保存不可。

## 正式公開より先に必要
1. 専用ギャラリーDBの識別子・既存テーブル定義・バックアップを確認する。
2. **別途承認を得てからのみ** `db/anniversary-background.sql` のマイグレーションを適用する。アプリのGET/POST時にDDLを実行しない。
3. 設定行を自動で作成しない。初回保存はrevision=0のときだけINSERT、2回目以降は一致revisionのUPDATE。
4. 模擬テスト `tests/mio-vnext-background.test.mjs`: 未準備時の安全な初期値、空テーブル、正常保存、管理者拒否、監査失敗ロールバック、競合、画面と画像切替コードを確認。
5. 管理者の承認済み端末で、姫→魔王→姫、同時操作で競合、ネットワーク切断、権限切れを検証する。
6. iPhone Safari、Android Chrome、PCでトップ・ギャラリー・ガチャを比較。文字を読みやすくし、画像の欠け・空白・誤切替がないことを確認。
7. 作品、ログイン、皆勤賞、ガチャ、参加者の本番データに影響がないことを最終確認してから、本番マージを別判断。
