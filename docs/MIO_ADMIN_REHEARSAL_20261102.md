# みおWeb運営管理センター：操作リハーサル（開発版のみ・2026-11-02）

## 今回できたこと
- 開発版 `/mio-admin-rehearsal.html` で、架空申請2件・架空参加者1名・架空障害2件を使った操作が可能。
- 申請の承認/却下、名前・デモID検索、参加者の選択、模擬ガチャ券1〜50回付与、操作IDの同一リクエスト再送排除/競合拒否、障害の未対応→対応中→解決済み、操作監査一覧、初期状態へのリセット。
- すべてブラウザメモリ内のデモ状態。更新すれば消える。URLに参加者検索情報を保存しない。架空の操作IDは `DEMO-` 接頭辞を要求する。
- 実管理パネル `gacha-web-gate.html` の **停止中** ブロック内にリハーサルへのリンクを設置した。本番の既存管理ボタン/受付スイッチの実装は変更しない。
- デモページ/JSは同じ既存Vercelプロジェクトの開発プレビュールートにだけ追加、`noindex`、`no-store`。新規GAS/Webアプリ/DB/別Vercel Projectは作成しない。

## 確認方法と検証範囲
- Nodeテストで既存本番97ビルド/31ルートと認証、ガチャ、皆勤などの元ファイルを保持したまま、2静的ルートだけ追加できていることを確認。
- Node側でデモJSの `fetch` / `XMLHttpRequest` / `sendBeacon` / `WebSocket` / `Cookie` / `localStorage` / `sessionStorage` / `indexedDB` / `innerHTML` と実API参照を禁止する検査を追加。
- Linuxの実Chromeモバイルエミュレーション320/375/390/430pxで画面が横にはみ出さないか検証。390pxで承認→参加者検索→模擬付与→同ID再実行→違う内容のID再利用を拒否→障害対応→リセットの順で実クリック。
- さらに架空申請の却下、模擬付与の0・51・1.5・マイナス値拒否、`DEMO-` 以外の操作ID拒否を回帰試験へ追加。受入判定はCIの最終ログを参照。
- 実ブラウザの証拠画像は GitHub Actions `mio-staging-mobile-chrome-evidence` に7日保持（個人情報なし）。
