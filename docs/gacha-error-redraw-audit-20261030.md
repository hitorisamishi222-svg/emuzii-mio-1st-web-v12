# ガチャ：エラー再抽選の履歴監査（2026-10-30）

## 安全条件
- このブランチは本番未反映。GAS稼働版を照合するまで本番に反映しない。URL/既存GAS/既存シート/当選/残回数はそのまま。
- GitHub main の Code.gs は古い v6。稼働中の v1.9.1 LOGIN-ID と同一とは限らない。main の Code.gs を直接本番へ全置換しない。
- 現在の当選履歴にはエラー経緯の識別欄がない。過去の確定結果を推測で再抽選扱いにしない。
- replayed:true は同じ抽選IDの確定結果を確認できたこと。新規再抽選と区別する。
- エラーで再抽選は、前回IDの確定履歴なし→本人の明示承認→同じIDで新規確定した場合のみ記録。
- 本人には自分の履歴のみ。管理者は既存の認可されたGoogle Sheetの全員分を見る。未認証で全員の当選結果を公開しない。

## 既存 v1.9.1 LOGIN-ID GAS への最小差分（稼働版の原本と照合後のみ）
1. 既存履歴シート emuzii_当選履歴 の O1 を「抽選経緯」に追加。A:N、K列の「確定」、当選IDは変更しない。
2. gachaAction_ の publicHistory の各行オブジェクトに historyKind: String(x[14]||'')==='エラーで再抽選'?'error_redraw':'' を加える。
3. previous（同じ drawId がすでに確定）レスポンスに historyKind: String(old[14]||'')==='エラーで再抽選'?'error_redraw':'' を加える。以前の行は更新しない。
4. 確定した新規行の appendRow に15番目の値 d.recoveryKind==='error_redraw'?'エラーで再抽選':'' を加える。drawId再送時は行を追加しない。
5. 新規抽選返却に historyKind: d.recoveryKind==='error_redraw'?'error_redraw':'' を加える。
6. setup() を本番中に再実行しない。O列の既存行は管理者が抽選IDと本人確認後にのみ手動で付けてもよい。

## 確認項目
- 通常抽選: O空欄、確定行1件、券1回消費
- 通信失敗後に元抽選がすでに確定: O更新なし、二重抽選なし、元結果を復旧表示
- 通信失敗後に元抽選が未確定: 同じID・本人同意で新規確定ならOへ「エラーで再抽選」
- 途中でリロード/連打: 元drawIdを保持して重複しない
- 過去の確定行およびテスト無効行: 無断変更なし
