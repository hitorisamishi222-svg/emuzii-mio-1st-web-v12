# ギャラリー管理者パスキー認証 — 実装仕様（未有効化）

## 確定ルール
- 初回の管理者（えむじー本人）は、公開ページから自己申告だけで登録できない。所有者の初回登録は既存の信頼済み経路で確認し、サーバー側で一度だけ有効化する。
- パスキーは WebAuthn（FIDO2）を使用する。認証器が作る秘密鍵はサーバーに送信しない。
- 公開サイトの HTTPS オリジンと RP ID を厳密に固定する。登録・認証のチャレンジはサーバーでランダム生成し、有効期限を短く設定して使い捨てとする。
- サーバーは credential ID、公開鍵、署名カウンタ、所属管理者、登録日時、失効状態を永続保存する。
- 管理者の追加・停止と端末の承認・取り消しは、えむじー本人の再認証を必須とする。
- パスキーの同期や別端末での認証成功だけでは新しい端末を承認しない。端末ごとの承認レコードをサーバーで確認する。
- パスキーと端末の承認が揃った管理者だけが画像をアップロードし、作品を公開・更新・削除できる。
- 投稿・更新・削除は監査ログを残し、サーバーで入力値、画像形式、容量、許可されたリンク先を検証する。
- 参加者用 MIO-ID・登録済み Cookie は管理者権限として利用しない。
- 既存の GAS、参加者データ、ガチャ API は変更しない。

## 現状
- ストレージ接続とモバイル編集プレビューは完了。
- WebAuthn の対応可否表示は実装済み。
- 所有者の初回登録、パスキーのチャレンジ発行・署名検証、端末承認 DB、投稿処理は未実装。
- これらが完成し実機テストに合格するまで公開 API は常に拒否する。

## 実装順
1. ギャラリー専用の管理者・端末・パスキー・監査ログ DB を用意する。
2. 初回所有者を安全な経路で登録する。メールアドレスやニックネームの自己申告だけでは登録しない。
3. WebAuthn 登録・ログインをサーバーで検証し、セッションを安全な HttpOnly Cookie で管理する。
4. 端末承認ワークフローを実装し、承認待ち端末には閲覧以外を許可しない。
5. Blob 保存と公開ギャラリー更新を、サーバーでの認可確認後だけ有効化する。
6. iPhone 実機と未承認端末で拒否テストを行ってから公開する。
