# 本人確認済みIDの統合・安全な公開チェック（2026-10-22）

## 目的
管理者が直接本人確認した複数の参加者IDと新規Web受付IDを、代表IDへ参照統合する。
元のフォーム回答、FA応募、皆勤、ガチャ、当選履歴、認証ハッシュを削除・名前変更・移動しない。

## 実装・検証済み（開発ブランチのみ）
- 代表IDと旧IDは別行のまま保持し、emuzii_本人統合で確認済み紐付けを記録する。
- Neon mio_registration_v2 に新規受付IDの承認・代表IDへの連携が保存されている。
- GASの新 integrateLight アクションでは、正しいブラウザID・名前・代表IDを管理者確認表で再照合する。トークン競合を拒否し、再実行時も二重行を作らない。
- 旧IDで引いた過去の当選履歴も代表IDの使用済み回数に含め、権利二重付与を防ぐ。
- 新規登録画面に、本人確認済み参加者だけが使用する明示的な有効化ボタンを追加する。
- GitHub Actionsで構文・統合・履歴保護のテスト合格。

## 本番公開の必須手順（順番厳守）
1. 稼働中の Google Apps Script プロジェクトの全ファイル・デプロイ版を読み取り専用で保存する。GitHub Code.gs と本番GASが一致する前提は禁止。
2. 差分を慎重に統合する。本番GASがGitHub版と異なる場合、既存機能を丸ごと上書きしない。既存URLを保った新バージョンでデプロイする。
3. emuzii_本人統合の確認済み記録、代表ID、旧ID、新規受付IDを照合する。原本に触れない。
4. 専用ブランチのVercelプレビューとGitHub CIが成功した後で、既存本番URLを保ってVercelサイトを更新する。
5. GASの integrateLight が本番で動作することを検証した後に限り、Vercel本番の MIO_ATTENDANCE_ACTIVATION=verified を設定してデプロイする。先行設定は禁止。
6. 対象者が元の新規登録ブラウザで /join.html を開き、管理者承認後の有効化ボタンを押す。GASの独立照合に成功した場合だけ認証Cookieを発行する。
7. 参加者の予想回答、FA3作品、皆勤日数、ガチャ残り回数、過去の当選履歴を読み取り専用で再確認する。
8. 参加者と履歴のスナップショットを突き合わせ、差異があれば新規連携を停止して元の版へ戻す。

## 運用上の制限
GitHub Code.gs の編集は実際の Google Apps Script プロジェクトの編集ではない。
現在利用可能な接続ツールからは Apps Script Projects API による本番GASのソース取得・更新ができない。本番認証の復旧完了とは報告しない。

## ロールバック
Vercel本番の MIO_ATTENDANCE_ACTIVATION を無効化して新規連携を停止し、必要に応じて前のVercelとGASのデプロイへ戻す。
元データをコピーし直すと重複するため、参加者・FA・皆勤・ガチャ・当選履歴の原本を復元目的で上書きしない。
